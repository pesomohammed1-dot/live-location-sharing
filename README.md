# هدية رقمية مع مشاركة موقع اختيارية

واجهة عربية بتصميم هدية أنيق. بعد فتح الهدية يظهر توضيح صريح بأن الميزة التالية هي مشاركة الموقع المباشر. لا يبدأ أي تحديد أو إرسال إلا بموافقة صاحب الجهاز وضغطه على زر البدء ثم موافقة المتصفح.

## المزايا
- شاشة هدية ثم إفصاح واضح وموافقة صريحة.
- مشاركة مباشرة عبر Firebase Realtime Database ورابط مشاهدة عشوائي 128-bit.
- إيقاف يدوي ومحاولة تعيين الحالة غير نشطة عند انقطاع الصفحة عبر Firebase onDisconnect.
- إشعار بريد واحد عند أول تحديث موقع ناجح، لا إشعارات متكررة مع كل تحديث. يتضمن الرابط والإحداثيات الأولى ورابط خرائط؛ وإذا فشل الإرسال يظهر زر لإعادة المحاولة يدوياً.
- وضع مشاهدة لا يطلب موقع جهاز المشاهد.

## Firebase
الإعدادات الحالية في `index.html` تخص مشروع Firebase الموجود.
1. فعّل Anonymous من Firebase Authentication.
2. تأكد من إنشاء Realtime Database وأن databaseURL مطابق لما في index.html.
3. انشر قواعد `database.rules.json` من Realtime Database > Rules.
4. لا تضع Service Account أو مفاتيح إدارية في ملفات الموقع.

**تنبيه أمني:** قواعد Firebase الحالية تسمح لأي مستخدم مسجل دخول مجهول بالقراءة والكتابة على غرف Realtime Database. رمز الغرفة يعمل كرابط حامل للصلاحية؛ لا تشاركه علناً. هذا ليس نظام صلاحيات عالي الضمان.

## تفعيل البريد (مطلوب لإرسال الإشعار)
GitHub Pages يستضيف ملفات ثابتة ولا يرسل البريد وحده. أعددنا التكامل مع EmailJS:
1. أنشئ حساباً في [EmailJS](https://www.emailjs.com/) واربط خدمة بريد.
2. أنشئ Email Template واجعل **To Email** ثابتاً على بريدك أنت، وليس قيمة يكتبها الزائر.
3. أضف المتغيرات التالية في القالب: `{{room_link}}`, `{{recipient_name}}`, `{{latitude}}`, `{{longitude}}`, `{{accuracy}}`, `{{maps_link}}`, `{{started_at}}`.
4. انسخ Service ID وTemplate ID وPublic Key.
5. الكود الحالي يستخدم Service ID بالقيمة `service_6sirvcc` وTemplate ID بالقيمة `template_ttechpb`، ويستخدم Public Key الموجود في `index.html`. إذا تغير أي منها، حدّث القيمة المطابقة في استدعاء `emailjs.send`.
6. تأكد أن محتوى قالب EmailJS نفسه يعرض المتغيرات التالية، وإلا قد تصل رسالة عامة دون بيانات الموقع: `{{room_link}}`, `{{latitude}}`, `{{longitude}}`, `{{accuracy}}`, `{{maps_link}}`, `{{started_at}}`. واجعل خانة **To Email** ثابتة على بريدك أنت.
7. احفظ التعديل على فرع `main`؛ ثم تحقق من نجاح نشر GitHub Pages من تبويب Actions.

لا تضع كلمة مرور بريدك أو EmailJS Private Key في كود الموقع. معرفات EmailJS الثلاثة المستخدمة هنا مخصصة للعميل، واجعل المستلم ثابتاً في القالب.

## النشر والاستخدام
- اختر GitHub Actions كمصدر في Settings > Pages.
- تابع [عمليات النشر](https://github.com/pesomohammed1-dot/live-location-sharing/actions).
- افتح الموقع على جهاز المشارك، ثم «افتح الهدية»، اقرأ الإفصاح، وافق، واسمح للموقع من المتصفح.
- أرسل رابط المشاهدة للشخص المقصود فقط، وأوقف المشاركة عند الانتهاء.

## حدود معروفة
- يجب أن تظل الصفحة مفتوحة والإنترنت متاحاً لتحديث الموقع.
- يُرسل البريد تلقائياً مرة واحدة بعد أول تحديث ناجح؛ وإذا تعذر الإرسال لا تتكرر المحاولات تلقائياً، ويمكن الضغط على زر «إعادة إرسال البريد».
- إذا لم تضبط EmailJS فستعمل مشاركة الموقع دون البريد.
- لا يوجد حذف تلقائي نهائي للغرف القديمة؛ راجع بيانات Firebase دورياً.
- لا تستخدم الصفحة لتحديد موقع أي شخص دون علمه وموافقته.
